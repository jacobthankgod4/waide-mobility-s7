Service 04

Accessible mobility and wayfinding.

Indoor navigation that accounts for lifts, ramps, closures and assistance points, and an interface that works with a screen reader as well as a screen.

Discuss a wayfinding project Read the technical note

The problem

A route that assumes stairs excludes people before they arrive.

Wayfinding is usually designed around the average visitor: someone who can walk, read a sign at a distance and use a staircase. Anyone outside that assumption depends on asking staff, or does not make the trip at all.

Accessible wayfinding is not a separate product bolted on at the end. It changes the spatial model: a step-free network is built alongside the standard one, with lifts, ramps, level access, accessible toilets, service desks and assistance points carrying their own attributes.

Scope

What this service covers.

Indoor navigation

Turn-by-turn routing from an entrance, car park or QR point to a unit, facility or service desk, across levels.

Accessible route mapping

A separate step-free graph using lifts, ramps and level access, with closures and temporary obstructions recorded.

Step-free route information

Routes presented in plain language, with the number of level changes and the facilities available along the way.

Accessible point-of-interest data

Entrances, accessible toilets, lifts, hearing loops, assistance desks and quiet spaces as structured, searchable features.

Audio and screen-reader support

Semantic markup, keyboard operation, focus management, live-region announcements and optional spoken directions.

Inclusive user testing

Route walk-throughs and interface testing with disabled users where the project and consent allow it, recorded as findings.

Method

How accessible routing is built.

  1. Audit the physical route

    Walk the building and record gradients, thresholds, door widths, lift dimensions and obstructions against the route network.

    OutputRoute condition register

  2. Build the accessible graph

    Create a step-free network with edge costs that account for level changes, distances and surface conditions.

    OutputAccessible network layer

  3. Attach facility data

    Link lifts, ramps, toilets and assistance points to the spaces they serve, with status and access notes.

    OutputAccessible POI dataset

  4. Build and test the interface

    Keyboard-only operation, screen-reader announcements, contrast, target size and reduced-motion behaviour are checked.

    OutputTested interface and issue log

  5. Validate on site

    Walk the generated routes with the venue team and, where possible, disabled users; correct mismatches and record the result.

    OutputRoute validation record

Outputs

What you receive.

  • A standard pedestrian network and a separate step-free network.
  • Accessible point-of-interest data with status and access notes.
  • A navigation interface that works without an installed app, where the scope calls for it.
  • An accessibility test record describing what was checked and what was found.
  • Plain-language route descriptions and on-site signage content where required.
  • A maintenance procedure so closures and changes are reflected in the routes.

Standards and evidence

Interface work follows established web accessibility practice: semantic structure, keyboard access, visible focus, sufficient contrast and no reliance on colour alone.

Questions

Common questions.

Does the visitor need to install an app?

Not necessarily. Browser-based access through a QR code is the default for visitor wayfinding, because it removes the install step. A native app is scoped only where there is a clear operational reason.

Can you retrofit accessible routes into an existing map?

Usually, if the underlying geometry and connectors are sound. If the existing network cannot express lifts and level changes properly, the route layer has to be rebuilt rather than patched.

How are temporary closures handled?

Through an update procedure: a named owner, a simple change record and a review cycle. The interface should never route someone into a closed corridor for weeks.
