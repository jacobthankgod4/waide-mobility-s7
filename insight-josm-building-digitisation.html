How we use JOSM to map a mall

JOSM is the editor we used for much of the Novare indoor map. This note explains how floor plans and site checks became connected map features, and where careful manual work was needed.

By ThankGod Jacob Chibueze · Waide Mobility

Why JOSM.

JOSM is an OpenStreetMap editor. It is not purpose-built for indoor mapping, and it does not look like a commercial GIS. It is useful here for three reasons: it handles relations and tags well, it works offline on a local extract, and its data model is open and inspectable.

For an indoor project, the alternative is usually a CAD trace in a desktop GIS. That works, but the result tends to be a set of polygons with attributes, not a connected topology. JOSM pushes toward shared nodes and explicit relations, which is closer to what routing needs.

The cost is that JOSM will accept almost anything. Tagging consistency is a project discipline, not a feature of the editor.

The workflow, in order.

  1. Prepare a local working file

    Create a separate .osm file for the building. Do not mix the indoor dataset into a live map extract you also edit for other purposes.

    CheckFile opens cleanly; no stray objects

  2. Set the imagery and reference frame

    Load the best available imagery and align it with the plan using identifiable control points. Record the offset and the residual error.

    CheckAlignment residual within the stated tolerance

  3. Draw the building outline and levels

    Create the outer shell, then separate level containers. Keep level names exactly as they appear on signage, with a short code for the database.

    CheckEvery level has a name and an order

  4. Trace units and circulation

    Draw unit polygons and the walkable area as separate features. Share nodes at doorways so the geometry is connected, not just visually adjacent.

    CheckNo unit overlaps a corridor polygon

  5. Add doors, lifts and facilities

    Place nodes for doors and vertical connectors, and tag them with access, level and step-free attributes. Add toilets, desks and assistance points.

    CheckEvery connector links two levels or two spaces

  6. Build and validate the route graph

    Create the pedestrian edges over the walkable area. Run topology checks, then walk a sample of routes on site and correct the graph.

    CheckAll destinations reachable; no wall crossings

Tagging decisions that matter.

Indoor tagging has a small vocabulary and a lot of local interpretation. The project needs a written convention, applied consistently, or the dataset becomes a pile of near-duplicates.

FeatureUseful attributesCommon error
UnitName, category, level, reference, accessUsing the tenant name as the only identifier
CorridorLevel, width, access, surfaceDrawing corridors as unconnected polygons
DoorAccess, automatic, width, step-freePlacing doors without connecting the shared node
LiftLevels served, capacity, access, statusModelling a lift as a single point with no level links
StairsLevels, direction, step-free = noForgetting to exclude stairs from the accessible graph
FacilityType, level, access, opening hoursMixing public and staff-only facilities in one category

Where automation helps, and where it does not.

Automated extraction can find building outlines, car park bays and some repeated features from imagery. It is less reliable for indoor units, door access rules and level connectors, because those depend on information that is not visible in a photograph.

In this project, parking geometry and building features were digitised manually, with field verification. Automated detection was not used and is not credited with the result. Manual tracing is slower, but it produces geometry that can be explained and corrected.

Do not overstate the method. If a feature was traced by hand, say so. If a model was used to suggest a boundary that a person then accepted, say that instead. The provenance of each feature is part of the dataset's quality.

Validation is a site activity.

Desktop validation catches geometry errors. It does not catch a door that is permanently locked, a lift that serves only the car park, or a corridor that is used for storage. Those are discovered by walking the building with the venue team.

A practical field check covers entrances, level connectors, the route from parking to the retail floor, and at least one destination of each type. Findings are logged with a photograph where permitted and a correction against the feature identifier.

What this produces.

The output is not a map image. It is an editable dataset with a schema, a tag convention, a route graph and a validation record. That is the asset a client can maintain, extend and export.

It is also the part that most digital twin marketing skips. A rendered model is easy to demonstrate. A routable, validated, maintainable indoor dataset is the work.
