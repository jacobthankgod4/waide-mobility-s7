2. Core services

  • Building and site maps: indoor and outdoor surveys, floor-plan mapping, turning CAD drawings into maps, and creating searchable place lists and routes.
  • Building maps and records: map floors, rooms and equipment, and connect them to existing facility records when the source information supports it.
  • Web maps and tools: web and mobile maps, directories, dashboards, and secure access for staff or visitors.
  • Accessible routes: step-free indoor routes, destination information, audio directions and screen-reader support.
  • Project advice and training: help with requirements, tool selection, data checks, staff training and documentation.

3. Technical expertise

The practice combines geospatial engineering with software delivery. Core technical areas include spatial schema design, indoor topology and routing, georeferencing, data quality assurance, web mapping interfaces, accessible interaction design and technical documentation.

Software engineering and automation are enabling capabilities. They support the geospatial work rather than constituting a separate general-purpose software service.

6. Technical methods

  • Source audit, georeferencing and documented digitisation.
  • Indoor feature schemas with stable identifiers and access classification.
  • Separate pedestrian, vehicle and step-free networks with explicit transfer nodes.
  • Dijkstra shortest-path routing with mode-specific edge costs.
  • Topology, completeness, positional and route validation checks.
  • Field verification against the physical building.

7. Project delivery approach

Delivery runs through ten stages: discovery and requirements; data assessment; data collection and preparation; architecture; engineering; integration; testing and QA; deployment and handover; documentation and knowledge transfer; support and maintenance. Three review gates control progression: scope and exclusions, schema and data rules, and acceptance criteria.

8. Quality and documentation

Deliverables are accepted against written criteria. The documentation set typically includes an architecture note, data dictionary, QA report, user and administrator guidance, and an update procedure. Waide does not claim formal quality certification.
